# Crypto Mission — 情報Ⅰ 暗号通信体験

高校「情報Ⅰ」の授業で，共通鍵暗号，公開鍵暗号，デジタル署名の違いをペアで操作しながら学ぶWeb教材です．1台のPCを2人で使い，「どの鍵を選ぶか」「なぜその鍵なのか」を相談するミッション形式になっています．

## 教材の目的

暗号方式の用語を覚えるだけでなく，Alice（送信者），Bob（受信者），Eve（盗聴者）の関係と，鍵を誰が持つかに注目して，通信の流れを説明できるようにすることを目的としています．公開鍵・秘密鍵・共通鍵のアイコンはすべて `🔑` に統一し，鍵の形や開閉のイメージではなく，ラベルと公開範囲で区別します．

## 学習目標

- 共通鍵暗号では，暗号化と復号にAliceとBobが共有する同じ鍵を使うことを説明できる．
- 公開鍵暗号では，受信者の公開鍵で暗号化し，受信者の秘密鍵で復号することを説明できる．
- Eveは暗号文を盗聴できても，秘密鍵がないため復号できないことを理解する．
- デジタル署名は秘匿ではなく，送信者の確認と改ざん検出を目的とすることを区別できる．
- 秘密鍵は本人だけが所持し，他人が自由に使える鍵ではないことを理解する．

## 使い方

1. `index.html` をブラウザで開きます．サーバやインストールは不要です．
2. 2人で相談しながら，STAGE 1から順番に取り組みます．
3. STAGE 2では，Alice → BobとBob → Aliceの両方向を試します．不正解の鍵も選び，表示される理由を確認します．
4. STAGE 3では署名を作成した後，Eveによる改ざんを行い，再検証の結果を比較します．

授業では，操作担当と説明担当を途中で交代する使い方を想定しています．

## GitHub Pagesで公開する

1. GitHubでこのリポジトリの **Settings** を開きます．
2. 左側の **Pages** を選択します．
3. **Build and deployment** の **Source** を `Deploy from a branch` にします．
4. Branchを `main`，フォルダを `/(root)` にして **Save** を押します．
5. 数分後に表示されるURLへアクセスします．通常は `https://ユーザー名.github.io/リポジトリ名/` です．

すべて相対パスで構成しているため，追加設定なしでGitHub Pagesから配信できます．

## 技術構成

- HTML5：画面構造とアクセシブルな操作要素
- CSS3：学校PCの横長画面を中心としたレスポンシブレイアウト
- Vanilla JavaScript：ステージ切替，鍵選択，通信結果，署名・改ざん体験
- Web Crypto API：デジタル署名ステージのSHA-256ハッシュ表示

外部ライブラリ，ビルド処理，外部APIは使用していません．

## 教育上の注意点

- 本教材は仕組みを理解するためのシミュレーションです．実際の暗号化・復号・電子署名の数学的処理や，証明書，認証局，鍵交換，暗号方式の安全性を完全に再現するものではありません．
- STAGE 2の「公開鍵で暗号化，秘密鍵で復号」は公開鍵暗号による秘匿の基本モデルです．実際の通信では，公開鍵暗号と共通鍵暗号を組み合わせたハイブリッド暗号が広く使われます．
- STAGE 3では学習上の流れを明確にするため，「ハッシュ値を秘密鍵で署名する」と表現しています．実際の署名方式では，パディングや署名方式固有の処理などが加わります．
- 公開鍵が本当にAliceのものであることを保証する仕組みは，本教材の範囲外です．必要に応じて電子証明書や認証局の学習へ接続してください．
