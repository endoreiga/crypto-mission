# 暗号通信ミッション

高校「情報Ⅰ」の「暗号とデジタル署名」で使用する，二人一組の体験型Web教材です．説明を読み進める教材ではなく，通信図を見ながら鍵を選び，起きた現象から鍵の役割を考えることを目的としています．

公開ページ：https://endoreiga.github.io/crypto-mission/

## 教材の位置付け

50分授業のうち，約22分のペアワークで使うことを想定しています．教師が事前に説明するのは，平文・暗号化・暗号文・復号・鍵，および公開鍵と秘密鍵の公開範囲までです．「誰のどの鍵を使うか」はアプリ上の試行錯誤を通して生徒が発見します．

この教材だけで授業内容を完結させるのではなく，体験後に教師が仕組みを整理し，生徒が振り返りを記述する授業構成を前提にしています．

## 学習目標

- 「誰の鍵か」「公開鍵か秘密鍵か」「何のために使うか」を関連付けて考える．
- 共通鍵暗号では，暗号化と復号に同じ共通鍵を使うことを理解する．
- 公開鍵暗号による秘匿では，受信者の公開鍵で暗号化し，受信者の秘密鍵で復号することに気付く．
- デジタル署名では，送信者の秘密鍵で署名し，送信者の公開鍵で検証することに気付く．
- デジタル署名の目的が秘匿ではなく，送信者の確認と改ざん検出であることを区別する．

すべての鍵は同じ `🔑` で表示し，所有者・鍵の種類・公開範囲の文字情報で区別します．

## 授業での使い方

1. ブラウザで公開ページを開き，二人で1台のPCを使います．
2. ステージ1から順に進みます．上部の進行表示で現在地と完了済みステージを確認できます．
3. 鍵を置く空欄を選び，鍵カードをクリックします．マウスでは鍵カードを空欄へドラッグすることもできます．
4. 「通信してみる」を押し，アリス・通信経路・ボブ・イブに起きる現象を観察します．
5. 成功しない場合も正解は表示されません．短い問いを手掛かりに二人で相談し，同じ画面ですぐ選び直します．
6. ステージ1終了時の表示に合わせ，操作担当を交代します．

主要な操作はボタンで構成しているため，`Tab` キーと `Enter` または `Space` キーでも操作できます．

## ステージ構成

### ステージ1：共通鍵暗号

アリスとボブがすでに同じ共通鍵を持つ状態で，暗号化・盗み見・復号の流れを観察します．最後に共通鍵そのものを通信経路で送るとイブにも知られる演出を行い，「共通鍵を最初にどう渡すか」という問題をステージ2へつなげます．

### ステージ2：公開鍵暗号

本教材の中心課題です．アリスの公開鍵・秘密鍵，ボブの公開鍵・秘密鍵から，暗号化と復号に使う鍵を選びます．誤った選択は「不正解」ではなく，「アリスはその鍵を持っていない」「イブが読めた」「ボブが読めなかった」など，起きた現象として示されます．基本問題の完了後，任意でボブからアリスへの逆向き通信にも挑戦できます．

### ステージ3：デジタル署名

目的が秘匿から送信者確認・改ざん検出へ変わることを明示し，署名と検証に使う鍵を選びます．正常な検証後，イブが「10時」を「8時」に書き換え，再検証でメッセージの指紋が一致しないことを観察します．SHA-256値は「詳しく見る」を開いた場合だけ表示します．

## GitHub Pagesで公開する

1. GitHubでリポジトリの **Settings** を開きます．
2. **Pages** を選びます．
3. **Source** を `Deploy from a branch` にします．
4. Branchを `main`，フォルダを `/(root)` にして保存します．

ビルド処理や環境変数は不要です．

## 技術構成

- HTML5
- CSS3
- Vanilla JavaScript
- Web Crypto API（SHA-256）

外部ライブラリ，外部API，ビルドツールは使用していません．GitHub Pagesからそのまま配信できます．横長の学校PC（1366×768程度）を主対象とし，スマートフォン向けにもレイアウトを切り替えます．

## 教育上の注意点

- 本教材は鍵の役割を学ぶ概念モデルであり，実際の暗号アルゴリズムや数学的処理を完全に再現するものではありません．
- 実際の通信では，公開鍵暗号と共通鍵暗号を組み合わせたハイブリッド暗号が広く使われます．
- 「ハッシュ値に秘密鍵で署名する」という表示は概念を整理したものです．実際の署名方式にはパディングなど方式固有の処理があります．
- 公開鍵が本当に本人のものかを保証する電子証明書・認証局は本教材の範囲外です．最終画面の問いから，次時の電子証明書・認証局・SSL/TLSへ接続できます．
